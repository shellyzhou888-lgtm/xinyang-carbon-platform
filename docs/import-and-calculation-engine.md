# 导入解析与计算引擎（v1.0）

> 日期：2026-10-20｜迁移 0013–0015、`packages/ingest`
> 状态：已在 `greensystem` 部署。导入与计算全链路已用测试数据端到端验证（事务回滚，未留数据）；22 条指标公式待审核后才能写入正式结果。

## 1. 整体流程

```text
企业填写 Excel 模板
   │
   ▼  packages/ingest（TypeScript，将来直接用于 Next.js 上传接口）
解析 Excel：按模板定位工作表和表头行；单元格统一转文本（日期、公式结果、富文本）
   │  缺必填表头 → 整个文件拒收；未识别的列 → 原样入湖并在批次备注中提示
   ▼
入湖（raw）：raw.document（文件信息，原件存 storage/uploads/年月/sha256.xlsx）
           raw.import_batch（批次） → raw.import_record（每行原样存 JSON）
   │
   ▼  engine.load_batch(批次)
入仓（fact）：按 core.import_field_map 把“宽表”拆成“长表”
           月度能耗 → fact.energy_activity；年度经济/产量 → fact.statistic_value
           是否规上/高企 → core.enterprise_profile
   │
   ▼  engine.run_all(标准, 节点, 年份)
calc_energy      单位换算 → 已批准的折标系数 → tce
calc_carbon      按标准的因子偏好选因子 → 910 号文口径碳排放（每条能源活动一条结果）
calc_indicators  公式求值 → 判定基准 → 是否达标、得分 → fact.indicator_value（附依据快照）
```

### 为什么这样分工

| 部分 | 放在哪里 | 原因 |
| --- | --- | --- |
| Excel 解析 | TypeScript | 数据库不能读 xlsx；网站是 Next.js，同一模块直接复用 |
| 入仓、计算 | PostgreSQL 函数（schema `engine`） | 网站、Pi Agent、数据管道调用同一套逻辑，结果一致；函数随迁移管理，可审计 |

## 2. 关键规则

### 2.1 导入

- **企业匹配**：先按统一社会信用代码，其次按企业法定名称或对象树名称。未登记的企业不自动新建，该行报错并提示先在后台登记，保证对象树受控。
- **逐行容错**：每行单独处理，一行出错只回滚该行，其他行照常写入；错误原因写入 `raw.import_record.error_message`。
- **重复上传**：同一企业、同一期间、同一品种只有一条当前数据。新值替换旧值，旧行标记为历史（`is_current = false`，`superseded_by` 指向新行）。值完全相同则跳过。
- **估值不覆盖真实数据**：AI 估值或插值不会替换实测、手工数据；反过来，真实数据会替换估值。
- **数据来源**：按模板下拉值映射为实测（measured）或手工（manual）；未填时按批次来源推断。

### 2.2 折标准煤

- 只使用**已批准**的折标系数。缺系数的能源不计入综合能耗，并在计算记录中列出。
- 折标系数单位为 kgce/X：先把用量换算到 X，再乘以系数、除以 1000 得到 tce。

### 2.3 碳核算（发改环资〔2025〕910 号附件 4）

| 能源类别 | 核算类别 | 说明 |
| --- | --- | --- |
| 煤、油、气 | 燃料燃烧 | 优先用单位排放因子，否则用“低位发热量 × 单位热值排放因子” |
| 电力 | 电力间接排放 | 电网电力按标准偏好选口径；绿电、直供非化石电力、自发电计 0 |
| 热力 | 热力间接排放 | 化石热力 0.11 tCO₂/GJ，非化石热力计 0 |
| 生物质、沼气，以及用作原料的能源 | 不计 | 生物质为生物源碳，原料不属于燃烧 |

- **送出、上网**：记为负值，体现“净受入”。
- **按口径分别存**：同一条能源活动，在绿色园区口径（河南省级电力因子）和零碳园区口径（全国化石能源电力因子）下各存一条结果，互不覆盖。
- **因子年份回退**：生态环境部电力因子一般滞后两年发布。数据年份还没有对应因子时，取该口径最近一年的因子，并在计算记录中提示，例如 `ELEC_GRID:henan:2025→2023`。

### 2.4 汇总范围

- **核算单元**：园区和片区的汇总只累加“企业”和“公共区域”两类节点。厂区、产线、设备的数据是分项计量，只用于能流和溯源，不重复计入。
- **统计量**：节点自身有数据时（如园区直接上报的用地面积）优先使用，否则累加下属企业。
- **缺数据与 0 区分**：没有数据返回空值，而不是 0，缺失时能被发现。
- **特殊基础量**：
  - 省以上绿色工厂总产值：由企业荣誉（绿色工厂、计入指标、获评年份不晚于统计年份）与企业总产值自动汇总。
  - 高新技术企业总产值：由企业档案的高企标记与总产值自动汇总。
  - 园区或企业直接上报了这两项时，优先使用上报值。

### 2.5 指标

- **公式求值**：公式里的基础量编码被替换成实际数值后再求值，支持 `cagr(X, n)`、`lag(X, n)`、`avg_dim(X, 维度)`。求值前会做安全检查，展开后只允许数字、运算符、括号。
- **只用已批准的公式**：
  - 正式模式只用已批准的公式，未批准的跳过并提示。
  - 预览模式（`preview`）可以使用草稿公式，结果只返回、不写入。
- **判定基准**：
  - 优先使用本指标自身的基准（满足适用条件时）。零碳园区单位能耗碳排放，会按园区年综合能耗自动选择 0.2 或 0.3 档。
  - 没有自身基准时，沿版本对照继承 2024 版引领值（对照关系为相同、改名、口径收窄的指标）。
- **得分**：分值加权的标准（2025、2026 版），达到判定基准记满分。官方计分细则公布后再调整。
- **依据快照**：每个指标值都保存公式、版本、输入变量及取值、缺失项、基准来源，供依据溯源和 Agent 解释。

## 3. 使用方法

首次使用：

```bash
cd packages/ingest
npm install
```

导入（先加 `--dry-run` 试运行，确认无误再去掉）：

```bash
npm run ingest -- 企业月度能耗.xlsx --template ENT_MONTHLY_ENERGY --dry-run
```

导入后立即计算：

```bash
npm run ingest -- 企业年度经济统计.xlsx --template ENT_ANNUAL_ECONOMIC --calc GIP_2026:XYEDZ:2025
```

只计算：

```bash
npm run calc -- --version GIP_2026 --node XYEDZ --year 2025 --preview
```

数据库中直接调用：

```sql
SELECT engine.load_batch(批次号);
SELECT engine.run_all('GIP_2026', 'XYEDZ', 2025);        -- 正式写入（只用已批准公式）
SELECT engine.run_all('GIP_2026', 'XYEDZ', 2025, true);  -- 预览（可用草稿公式，不写入）
```
