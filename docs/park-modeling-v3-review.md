## 问题与判断

## 工序与工具证据

使用 build-3d-game-rooms 的自定义室外审阅适配：整区 macro → 全四区灰模 → structural refinement → 材质/植被 → 实际渲染审阅。外观未得到用户确认，因此在运行时导出前停止。

所有三维操作都走固定版本 `mcp-for-blender==2.2.2` 的 `execute_blender_code`。本地准备/归档脚本只处理 JSON、哈希和 HTML，不执行 bpy。原始调用保存在被忽略的 `storage/tooling/blender-mcp/audit/v3-*.json`；可移植摘要在 v3 的 `review/mcp-evidence.json`，包含失败与成功记录。

复现顺序（每一步用独立 MCP 调用，统一前置 `revision-v3-common.py`）：

1. `python3 scripts/prepare-park-revision-v3.py` 生成初始 `scene-contract.json`。
2. 经 MCP 单独打开未改动的 `assets/blender-models/v2/park-assemblies-v2.blend`。
3. `revision-v3-01-macro.py`；`revision-v3-02-depth-check.py`；用 `revision-v3-render.py` 输出四区灰模并检查。
4. `revision-v3-03-architecture.py`；`revision-v3-04-landscape.py`。
5. 检查彩色图后执行 `revision-v3-05-review-refine.py`、`revision-v3-05b-canopy-coverage.py`。
6. 用 `revision-v3-render.py` 输出各区 overview/detail/plan；顶视检查后执行 `revision-v3-05c-paving-review.py` 和 `revision-v3-05d-water-clearance.py`，再执行 `revision-v3-06-audit.py` 修正全区顶视取景、保存主工程并回到 GH 相机；重出受影响的画面。
7. `python3 scripts/package-park-revision-v3.py` 生成交付对照和证据。

调用示例：

```bash
bash scripts/blender-mcp-macos.sh call \
  --library scripts/blender/revision-v3-common.py \
  --code scripts/blender/revision-v3-03-architecture.py \
  --data assets/blender-models/v3/scene-contract.json \
  --output-dir assets/blender-models/v3 \
  --label v3-structure --user-prompt '按概念图和实景照片修正建筑同质化'
```

渲染脚本额外用 `--define '{"ZONE":"GH","VIEW":"overview","GRAY":false,"WIDTH":1600,"HEIGHT":1000}'`。不要在已经执行完相同阶段的 v3 场景直接重复构建：部分步骤会拒绝，另一些会重复移动或添加。

## 审阅发现与修复

- EEVEE 首轮存在近地道路/水面显示异常，改用 Cycles 并核对实际图；相机裁剪范围调整，灰模使用分灰度的 Workbench。早期灰模快照用于追溯，最终材质以最终工程/彩色渲染为准。
- 北湖凹岸水面改用明确条带四边面，避免依赖大凹多边形的自动三角化；岸线做确定性平滑。
- 首轮彩色图仍过于疏散和单调，二次修订家居间距、商业侧翼、屋顶明度、地表斑驳、水面法线、自然树冠覆盖和相机。
- 保持五类冠形，压缩不可见细分以满足每场景 150 万三角面目标和 GitHub 单文件限制；不删除原 v2 资源。
- 顶视检查发现厂房铺装共面重叠黑斑，合并家居紧凑厂群铺装并给电子区重叠铺装微小高差；按完整构图范围与画幅比例重算顶视镜头，避免边缘组团被裁切。
- 全构图顶视进一步发现四处背景水塘与道路冲突，移动未测绘的 GH/RD 水塘出道路并清理新水域内冠枝；不凭空补桥。道路/水面仅做这些明确位置的检查，不冒充全场景碰撞认证。

## 尚未解决的质量边界

仍有沙盘感，尚未达到概念图的实景级密度、细节、地形与远景表现。部分结构是参考推定而非可验证的单体正交复原；不能称为准确竣工模型。验证只覆盖场景/建筑/相机清单、分区隔离、三角面预算和外部依赖，不宣称全面穿插检查、测绘一致或运行时性能已达标。

外观确认前不导出新版 GLB，不更新网站；下一步应由用户对对照图确认构图与密度，再逐区做重点单体和环境细化。

## 复盘（待确认的经验，不直接升级为项目规则）

- 整园不等于复制数量越多；先在概念同机位核对主要体量的屏幕占比与空地关系。
- 颜色统一不能替代材料分类；自然植被应区分冠形、年龄尺度、群落覆盖与养护边界。
- 技术验证成功不等于外观通过，阶段图必须和审批状态一起交付。
