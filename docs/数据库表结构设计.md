# 数据库表结构设计（v1.0 草案）

> 日期：2026-10-20｜数据库：服务器 PostgreSQL 17.5 `greensystem`
> 依据：[平台功能架构与指标体系梳理](平台功能架构与指标体系梳理.md) v2.2
> 状态：**角色和 schema 已创建（0001）**；表结构（0002–0004）已在事务中试跑并回滚，**等确认后正式建表**。

## 1. 角色（已创建）

权限放在不能登录的**组角色**上，登录账号加入组角色即可获得权限。数据库里没有为新角色设置任何密码。

| 角色 | 类型 | 权限 | 当前成员 |
| --- | --- | --- | --- |
| `postgres` | 超级用户 | 全部 | 人工管理员：执行迁移、建角色、备份 |
| `greensystem` | 库所有者 | 拥有 6 个业务 schema 及其中对象 | 迁移时由 `postgres` 以 `SET ROLE greensystem` 切入 |
| `green_etl` | 组角色 | core 只读；raw、fact 读、写入、更新 | 暂无（数据管道上线时新建登录账号加入） |
| `green_app` | 组角色 | core、raw、fact、agent 读、写入、更新；mart、audit 只读 | `zyz`（开发期网站账号） |
| `green_agent_ro` | 组角色 | 只能读 mart 视图 | 暂无（Pi 查询 Agent 上线时新建登录账号加入） |

- 所有角色都**没有 DELETE 权限**。更正数据时用新行替换旧行，旧行标记为失效（`is_current = false`），不做物理删除。
- 只有 `greensystem` 能执行 DDL（建表、改表等结构变更），并且只通过 `database/migrations` 中的迁移文件执行。
- 给只读 Agent 建登录账号时，要在该账号上设置 `statement_timeout`（建议 5s）和只读事务（`default_transaction_read_only = on`）。

## 2. schema 分层

```text
raw   数据湖：原样保存导入文件、表格行、接口报文、AI 估值批次
  ↓ 清洗、校验、单位换算、来源标记
fact  事实：月度能源活动、统计台账、碳核算结果、指标值、佐证、预警、策略、预测
  ↑ 引用
core  主数据与配置：对象树、企业、荣誉、能源品种、因子、指标体系、公式、规则、策略库、术语
  ↓
mart  只读视图：页面与 Agent 的唯一查询入口
agent Agent 会话、消息、工具调用日志
audit 迁移登记、配置与指标值的变更审计
```

## 4. 关键设计说明

### 4.1 数据来源与版本

每条事实数据都有以下字段：
- `data_source`：来源（实测、手工、AI 估值、插值）。
- `quality_flag`：质量标记。
- `batch_id`：所属导入批次。
- `is_current`：是否为当前有效版本。

替换规则：
- **真实数据替换估值**：写入新行，旧行置 `is_current = false` 并用 `superseded_by` 指向新行。
- **唯一约束**：部分唯一索引保证同一节点、同一月份、同一能源品种只有一条当前有效数据。

依据溯源和数据管理后台能看到每个数的来源，前台达标卡片不显示来源标记。

### 4.2 碳核算口径

按发改环资〔2025〕910 号附件 4：园区排放 = 化石燃料燃烧 + 能源加工转化 + 电力净受入 + 热力净受入 + 工业过程。

在表结构上的落实：
- **电力**：用 `energy_type.electricity_kind` 区分电网电力和直供或绿证绿电。
- **受入与送出**：用 `flow` 区分，送出部分在 `carbon_emission.co2_t` 中记为负值。
- **用作原料的能源**：由 `use_type = 'raw_material'` 标识，计入综合能耗，但不计燃烧排放。

### 4.3 指标计算与达标展示

```text
statistic_value / energy_activity → 三级基础量
        → formula（已审核）→ indicator_value（数值、折算值、得分）
        → 对比 indicator_benchmark → achieved
        → mart.v_indicator_display（只返回已达标的指标）
```

- **评分方式**：按 `standard_version.scoring_method` 区分。2024 版是绿色指数；2025 和 2026 版是分值加权；零碳园区是阈值判定。
- **2026 版缺少的分值**：先空着，在 `indicator_def.score` 中补，不用改结构。

### 4.4 对象树

- **路径维护**：`org_node.path` 以 `node_id` 为标签，由触发器维护；移动节点时下级路径会自动级联更新（已在试跑中验证）。
- **汇总查询**：汇总某片区时用 `path <@ '1.3'` 查出整棵子树。
