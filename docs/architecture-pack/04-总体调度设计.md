# 总体调度设计：园区总管 Agent

文档版本：v1.0（2026-10-22，对应仓库 v0.51.0）　代码：`packages/db-agent/src/manager.ts`、`tools.ts`、`prompt.ts`、`voice-tools.ts`

---

## 1. 要解决的问题

平台有总览、能源、碳排、诊断、名录、数据治理六个板块，用户可能用文字或语音提问，问题经常跨板块（例如“今年碳排放下降主要靠哪家企业，有没有达到绿色园区指标”）。如果每个板块各做一个 Agent，再由一个“路由”Agent 转交，会出现：转述丢信息、各 Agent 口径不一致、多次调用模型变慢。

**设计选择：一个总管 Agent，直接持有所有只读工具，自己判断板块、自己调工具、自己汇总**。板块只作为“工具使用指引”写进系统提示词，不再拆成多个 Agent。

---

## 2. 整体结构

```
网页文字（ChatPanel）──► /api/agent（SSE 流式）──┐
                                                ├─► 总管 Agent（Pi Agent + DeepSeek）
小云语音（千问实时）──► ask_platform_manager ────┘        │
                                                         ├─ 系统提示词：业务背景 + 板块指引 + 回答规则
                                                         ├─ 13 个只读工具（同网站共用查询函数）
                                                         └─ 审计：agent.session / message / tool_call
                                                                   │
                                                        PostgreSQL（只读事务、最小权限角色）
```

- 文字和语音进入**同一个**总管，回答口径一致；审计记录中 `channel` 分别为 `web` / `voice`，`agent_name = platform_manager`。
- 千问只负责“听、说、页面动作”（如切换年份）；所有园区业务问题都交给总管，语音层不复制业务规则。

## 3. 板块与工具指引

工具按板块列出，但总管可跨板块组合使用：

| 板块 | 关注点 | 常用工具 |
|---|---|---|
| 园区总览 | 跨板块汇总、年度比较、达标概览 | `get_energy_summary`、`get_carbon_summary`、`get_indicators`、`get_data_coverage`、`get_weather_data` |
| 能源管理 | 综合能耗、品种、企业用能、强度、能源因子 | `get_energy_summary`、`get_factors`、`get_data_coverage`、`get_weather_data` |
| 碳管理 | 碳排放、来源、碳强度、碳因子、碳市场、产品碳足迹 | `get_carbon_summary`、`get_factors`、`get_data_coverage` |
| 综合诊断 | 指标、未达标原因、预测、预警、改进建议 | `get_indicators`、`explain_indicator`、`list_governance_issues` 等 |
| 企业与项目名录 | 企业识别、荣誉、排名、单企业能耗与排放 | `get_energy_summary`、`get_carbon_summary` |
| 数据治理 | 数据覆盖、模拟值、来源、口径、语义目录、工单 | `get_data_coverage`、`list_governance_issues`、`explain_indicator` |

所有板块共用：`search_catalog`（检索语义目录）、`plan_joins`（规划多表连接）、`query_metric`（按指标编码取值）、`query_sql`（受限自写 SQL）、`find_entities`（企业 / 对象名称模糊识别）。

写入类工具（`run_calculation`、`import_excel`、`execute_write_sql`）**对总管关闭**（`writeMode: "off"`）。用户要求改数据、导入、审批时，总管说明需要走有权限的管理流程。

## 4. 一次提问的执行过程

1. **补上下文**：`managerPrompt` 在问题后附上当前网页路径与统计年份（例如“/carbon，2025 年”），用于理解“本页”“今年”；用户明确指定时以用户为准。
2. **模型判断**：DeepSeek 根据系统提示词判断涉及哪些板块，决定调用哪些工具。
3. **执行工具**：工具顺序执行（`toolExecution: "sequential"`），每次在独立只读事务中运行，切换到最小权限角色。
4. **钩子控制**：
   - `beforeToolCall`：单次提问工具调用超过上限（默认 20 次）即终止，按已有结果回答；
   - `afterToolCall`：记录工具名、参数、耗时、成败、错误信息到 `agent.tool_call`。
5. **回答**：先结论，再列数字、年份、单位、口径；文字以 SSE 流式推送给网页，语音由千问合成播放。

## 5. 系统提示词中的关键规则

| 规则 | 目的 |
|---|---|
| 业务数据回答前必须实际调用工具取证，不编造工具结果 | 防止模型“背答案” |
| 写 SQL 前先检索语义目录，多表连接先规划 | 降低自写 SQL 出错率 |
| 没有查询可比年份时不得声称增长或下降 | 防止把单年数值说成趋势 |
| 引用出处只说官方文件全称、发文机关和文号，不提页码、本地文件名或路径 | 对外表述规范 |
| 不主动附加“模拟数据 / 仅供演示”提示；用户问到数据来源时如实说明来源与占比 | 汇报场景简洁，同时保留可追溯性 |
| 用户要求改数据时说明总管只读 | 权限边界 |
| 全部使用中文 | 面向园区用户 |

系统提示词还包含 `BUSINESS_BACKGROUND`：园区概况、四个片区、核算口径（910号附件4）、评价标准（《绿色工业园区评价要求》2026 版 19 项指标）、数据来源说明。

---

## 6. 安全边界（三层）

1. **工具层**：模型只能调用定义好的工具，不能直连数据库；`query_sql` 只允许单条 SELECT，并在 `green_agent_ro` 角色、只读事务、超时限制下执行。
2. **数据库层**：只读事务中任何写操作都会被 PostgreSQL 拒绝；`green_block_drop` 事件触发器禁止删除表。
3. **审计层**：每次会话、消息、工具调用都可追溯。

---

## 7. 质量保障

- 回归测试：`packages/db-agent/eval/cases.json` 收录 18 个典型问题，每题配标准答案 SQL；`npm run eval -- --manager` 用总管作答，检查回答中是否出现全部正确数值。最近一次结果 18/18。
- 抽查场景：天气查询、跨板块归因、拒绝写入请求均按预期处理。
