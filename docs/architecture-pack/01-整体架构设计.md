# 整体架构设计：从数据层到应用层

文档版本：v1.0（2026-10-22，对应仓库 v0.51.0）

本文按“数据怎么进来 → 存在哪 → 怎么算 → 怎么被取出 → 怎么展示和对话”的顺序，说明每一层用什么实现、代码在哪、层与层之间怎么调用。数据库表结构见 [02-数据库设计](02-数据库设计.md)，AI 部分见 [03](03-数据库Agent设计.md)、[04](04-总体调度设计.md)。

---

## 1. 分层总览

| 层 | 职责 | 实现 | 代码位置 |
|---|---|---|---|
| L0 数据来源 | 企业报表、公开数据、外部接口、模拟数据 | Excel 模板；高德天气、NASA POWER；天工 LCI 文件 | `templates/`、`data/`、服务器 `D:\10.19数据集` |
| L1 接入层 | 校验、入批次、写原始记录 | TypeScript + ExcelJS；网站上传接口 | `packages/ingest`、`apps/web/app/api/admin/import` |
| L2 存储层 | 原始、主数据、事实、展示、语义、审计 | PostgreSQL 17.5 + TimescaleDB 2.22 | `database/migrations/0001–0034` |
| L3 计算层 | 折标、碳核算、指标、预警；预测；产品碳足迹 | PostgreSQL 函数；Python（Chronos-2、Brightway） | `engine` schema、`packages/forecast`、`packages/lca` |
| L4 服务层 | 只读查询函数、AI 工具、总管 Agent | TypeScript（Pi Agent + DeepSeek） | `packages/db-agent` |
| L5 接口层 | 页面服务端取数、对话流、导入、报告、地图代理 | Next.js 服务端组件与 Route Handlers | `apps/web/lib/server.ts`、`apps/web/app/api/*` |
| L6 应用层 | 大屏、工作台、地图、图表、语音 | React 19 + 高德 + AntV L7 + ECharts + motion；小云语音 | `apps/web/app/(platform)`、`apps/web/components` |

依赖方向严格自下而上：网页不写 SQL，只调用 `packages/db-agent` 导出的函数；AI 工具与网页共用同一批查询函数，因此**同一个数字在网页、AI 文字回答、语音回答中一致**。

## 2. L0–L1：数据如何进入系统

### 2.1 四类标准模板

| 模板编码 | 内容 | 粒度 |
|---|---|---|
| `ENT_MONTHLY_ENERGY` | 企业月度能耗：电网电力、绿电交易、自发光伏（自用 / 上网）、天然气、外购热力、柴油等 | 企业 × 月 |
| `ENT_ANNUAL_ECONOMIC` | 工业总产值、增加值、员工、规上 / 高企标记 | 企业 × 年 |
| `ENT_ANNUAL_PRODUCTION` | 产品产量 | 企业 × 产品 × 年 |
| `PARK_ANNUAL_RESOURCE_ENV` | 用水、用地、固废、废水、污染物、绿色建筑、余热 | 园区 × 年 |

### 2.2 导入流程

```
Excel ──► 校验（dry run，事务回滚，不落库）
      ──► raw.import_batch 新建批次（来源类型、来源文件、估算方法与假设）
      ──► raw.import_record 逐行保存原文（JSON）
      ──► engine.load_batch：按字段映射拆成 fact.energy_activity / fact.statistic_value
            · 同一对象、同一期间、同一口径已有当前值 → 旧行 is_current=false，新行指向旧行（不删除）
      ──► 可选 --calc：engine.run_all 重算
      ──► governance-hook：登记语义目录、起草字段说明、跑检测规则
```

入口有三个，走同一套代码：网站“后台 → 数据管理 → 导入数据”（`/api/admin/import`）、命令行 `npm run ingest`、AI 的 `import_excel` 工具（默认关闭写权限）。

### 2.3 外部数据同步

- 天气：`npm run sync:weather`（高德实况 / 预报、NASA POWER 逐小时），Windows 计划任务定时执行，写入 `fact.weather_hourly`（TimescaleDB 超表，按月分块，210 天前自动压缩），连续聚合视图 `mart.weather_hourly_daily` 每小时刷新。
- 企业目录：`npm run sync:directory`。
- 天工 LCI：从服务器复制到 `storage/lca/`（不进 Git），由 `packages/lca` 处理。

## 3. L2：存储分层

| schema | 作用 | 典型表 |
|---|---|---|
| `raw` | 原样保存每次导入 | `import_batch`、`import_record` |
| `core` | 主数据与配置：组织树、能源品种、因子、指标定义与引领值、公式、策略、荣誉、企业目录 | `org_node`、`factor`、`indicator_def`、`formula` |
| `fact` | 事实数据（带版本） | `energy_activity`、`carbon_emission`、`statistic_value`、`indicator_value`、`alert_event`、`forecast`、`target`、`weather_hourly` |
| `engine` | 计算函数 | `load_batch`、`calc_energy`、`calc_carbon`、`calc_indicators`、`evaluate_alerts`、`run_all`、`metric_value` |
| `mart` | 给网页与 AI 的只读展示视图 | `v_indicator_display`、`v_screen_honor`、`weather_hourly_daily` |
| `semantic` | 语义目录与治理 | 表/字段说明、检测规则、工单、发布事件 |
| `agent` / `audit` | AI 会话与工具调用审计；迁移记录与变更日志 | `agent.session`、`audit.schema_migration` |
| `lab` | 试验性模块（批准后再迁到业务 schema） | `lca_process`、`lca_contribution`、`product_chain`、`product_chain_stage` |

每条事实数据都带：数据来源（实测 / 手动 / 估算 / 插值）、导入批次、是否当前版本。

## 4. L3：计算层

### 4.1 数据库计算引擎（实时、口径统一）

`engine.run_all(标准版本, 节点, 年份)` 依次执行：

1. **折标** `calc_energy`：活动量 × `core.factor` 中 `std_coal` 因子 → tce。电力按当量值 0.1229 kgce/kWh。
2. **碳核算** `calc_carbon`：按《工业园区碳排放核算方法》（发改环资〔2025〕910号附件4）。
   - 燃料：活动量 × 低位热值 × 单位热值含碳量 × 碳氧化率 × 44/12；
   - 外购电力：当年电网排放因子（口径 `national_excl_market_nonfossil`，逐年取值）；外购热力 0.11 tCO₂/GJ；
   - 绿电交易、自发光伏为零；上网电量按净受入扣除。
3. **指标** `calc_indicators`：解析 `core.formula` 中经人工批准的公式，结果写 `fact.indicator_value`，并与 `core.indicator_benchmark` 比较得出是否达到引领值。
4. **预警** `evaluate_alerts`：同比偏离 >10%、累计超预算、指标未达标、单位产值能耗高于园区均值 2 倍等规则，`root_cause` 记录主要贡献企业，供实景诊断落点。

查询时统一用 `engine.metric_value(指标编码, 节点, 年份, 口径)`，网页与 AI 都不自己拼公式。

### 4.2 离线模型（批处理、结果写回）

| 模块 | 技术 | 输入 | 输出 |
|---|---|---|---|
| 能碳预测 `packages/forecast` | Python 3.13 + Chronos-2（PyTorch） | 2021 年起各对象月度 tce、tCO₂ | `fact.forecast`：未来 12 个月 10/50/90% 分位；达峰路线图两种情景 |
| 产品碳足迹 `packages/lca` | Python 3.12 + Brightway 2.5（bw2data、bw2calc） | 天工 LCI 过程与交换、IPCC GWP100 因子；产业链模拟物料清单 | `lab.lca_process`（5,572 个过程足迹）、`lab.product_chain*`（两条产业链碳轨迹） |
| 模拟数据 `packages/ingest/sim` | TypeScript，固定随机种子 | `data/simulated/assumptions-v2.json` | 标准模板 Excel，再走正常导入 |

离线模型每次运行都登记批次（`fact.calc_run` 或 `raw.import_batch`），旧结果保留。

## 5. L4：服务层（`packages/db-agent`）

一个 TypeScript 包，同时被网站和 AI 使用：

- **查询函数**：`getParkOverview`、`getChartData`、`getManagementData`、`getCarbonManagementData`、`getEnterpriseMonthly`、`getEnterpriseEnergyMix`、`getIndicatorBoard`、`getCarbonAsset`、`getProductChains` 等。每个函数在 `readOnly()` 中执行：开启只读事务 → `SET LOCAL ROLE green_app` → 查询 → 回滚。
- **连接池**：`pg.Pool`，最大 8 连接，20 秒回收空闲连接、TCP 保活、8 秒连接超时、60 秒查询超时——数据库经 SSH 隧道访问，隧道断开时页面会快速报错并恢复，不会长时间挂起。
- **AI 工具**：16 个工具（13 个只读 + 3 个写入，写入默认关闭），封装上述查询、语义目录检索、受限 SQL。
- **总管 Agent**：见 04 号文档。
- 构建：`npm run build`（esbuild 打包为 `dist/*.mjs`），网站通过 `@xinyang/db-agent` 引用。

## 6. L5：接口层（Next.js 服务端）

| 路径 | 作用 |
|---|---|
| 页面服务端组件（`app/(platform)/**/page.tsx`） | 读取 URL 中的年份与标签 → 并行调用 `lib/server.ts` 中的函数 → 渲染。设为 `force-dynamic`，每次请求取最新数据 |
| `/api/agent` | 文字对话：POST 问题 → 以 SSE（Server-Sent Events）流式返回文本增量和工具调用事件；每个浏览器会话在内存中保留一个总管实例 |
| `/api/admin/import`、`/api/admin/templates/[code]` | 上传校验导入、下载模板 |
| `/api/diagnosis/report` | 把诊断数据交给 DeepSeek 生成减碳报告正文，前端拼成可打印 PDF |
| `/api/health` | 数据库、AI、语音后台连通性（顶栏状态灯） |
| `/api/map/config`、`/_AMapService/*` | 下发高德 Key、代理高德安全接口（不在前端暴露密钥） |
| `proxy.ts` | 登录守卫：校验签名 Cookie，未登录跳转 `/login`，接口返回 401 |

## 7. L6：应用层

### 7.1 页面结构

| 页面 | 主要内容 |
|---|---|
| 总览 `/` | 卫星 3D 地图为底，左侧达标指标 + 荣誉 + 能源简报，右侧重点排放企业 + 碳排简报；片区切换进入建筑尺度 |
| 能源 `/energy` | KPI；能耗热力孪生、月度与结构、企业用能矩阵、预算进度、指标表现；可再生能源；能源强度；能流网络地图 |
| 碳排 `/carbon` | 排放与范围、变化归因瀑布图、企业四象限、预算与达峰、指标表现；碳流网络；碳资产；产品碳足迹（碳轨迹） |
| 诊断 `/diagnosis` | 01 实景诊断（地图定位预警 + 联动诊断卡）→ 02 碳评价（19 项指标刻度）→ 03 能耗优化（策略、预测、减碳路线） |
| 名录 `/enterprises`、后台 `/admin` | 企业与项目目录；数据管理、指标体系、数据治理审核 |

桌面端工作页“一屏固定”：页面不整体滚动，用标签切换视图，长列表在面板内滚动。

### 7.2 地图与可视化组件

| 组件 | 技术要点 |
|---|---|
| `lib/park-map.ts` | `useParkMap` 创建高德 3D 地图并叠加 L7 场景；片区数据、`smoothRing` 曲线边界、锥形图标、信息卡 Canvas 绘制、倾斜取景 `frameParkTilted` |
| `ParkSpatialOverview` | 总览地图、片区视图、企业详情 |
| `EnergyHeatTwin` | 点阵 + 高斯核扩散热力、月份时间轴、年份切换 |
| `FlowNetworkMap` | L7 弧线三层（底弧、流光、箭头贴图），按能源品种筛选 |
| `SpatialDiagnosis` | 卫星近景、锥形箭头 + 波纹、预警落点、联动诊断卡 |
| `ProductTrajectory` | ECharts 瀑布图 + 累计折线 + 里程碑标注 |
| `IndicatorScales`、`ProgressViz`、`CarbonViews` | 指标刻度条、胶囊柱、企业矩阵、范围拆分、四象限、仪表盘 |

### 7.3 主题与样式

CSS 变量统一配色（深色 / 浅色两套），荧光黄 `#d4f75c` 作导航与选中色，翠绿表示能源、琥珀表示碳排。地图上的浮层不用背景模糊（避免拖动时逐帧重算）。

### 7.4 语音

浏览器端 `@xiaoyun/voice` SDK（小云形象、录音、播放、唤醒词）；后台 `npm run voice` 启动小云服务（端口 8766），连接千问实时语音模型；业务问题通过 `ask_platform_manager` 交给同一个总管 Agent（见 04 号文档）。

## 8. 一次请求是怎么走的（举例）

**打开“碳排管理 → 产品碳足迹”**

1. 浏览器请求 `/carbon?tab=product` → `proxy.ts` 校验登录 Cookie。
2. 服务端组件并行调用 `overview(2025)`、`management(2025)`、`productChains()` 等。
3. `productChains()` → `getProductChains()` → `readOnly()`：只读事务读 `lab.product_chain`、`lab.product_chain_stage`、`lab.lca_process`。
4. 服务端渲染 HTML，客户端组件 `ChainTrajectory` 用 ECharts 画碳轨迹瀑布图。

**问小云“万华去年排放多少”**

1. 千问实时语音识别出文字，判断是业务问题 → 调用 `ask_platform_manager(question, page, year)`。
2. 小云后台调用 `askManager` → 总管 Agent 选择 `get_carbon_summary` → 只读查询 → 得到数字。
3. 总管生成中文回答 → 返回千问 → 合成语音播放；全过程写入 `agent.session / message / tool_call`。

## 9. 部署与运维

| 项 | 现状 |
|---|---|
| 数据库 | 远程 Windows 服务器 PostgreSQL，仅监听本机；开发机通过 `scripts/start-db-tunnel.ps1` 建 SSH 隧道（本机 15432 → 服务器 5432），断线自动重连 |
| 网站 | `apps/web` 运行 `next dev --port 3001`（开发）；生产可 `next build && next start` |
| 语音 | `apps/web` 运行 `npm run voice`（端口 8766） |
| 定时任务 | Windows 计划任务：每小时语义治理（`install-governance-task.ps1`）、天气同步（`install-weather-tasks.ps1`） |
| 迁移 | `scripts/apply-migrations.ps1`，单事务执行，记录到 `audit.schema_migration`（当前 0034） |
| 版本 | Git + GitHub 私有仓库，每次任务更新 `VERSION`、`CHANGELOG.md` 并打 `vX.Y.Z` 标签 |
| 密钥 | `.env`、`apps/web/.env.local`、`apps/web/.env.xiaoyun` 均被 Git 忽略；postgres 管理员密码用 Windows DPAPI 加密保存在本机 |

## 10. 已知限制

- 大部分业务数据仍为模拟值，预测回测与产品足迹只说明方法可行，真实数据接入后需复核。
- 热力孪生是基于企业点位的空间扩散模型，不是厂区分项计量。
- 产品碳足迹的物料清单、产量、运输为模拟；部分天工过程用相近过程替代（已在页面注明）。
- 数据库经 SSH 隧道访问，服务器侧连接偶有中断。
