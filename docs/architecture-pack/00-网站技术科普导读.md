# 网站技术科普导读：信阳经开区能碳管理平台是怎么做出来的

资料包版本：2026-10-22（对应仓库 v0.51.0）　适合对象：第一次了解本项目的老师、同学或评审

> 读完这一篇，你应该能回答：网站由哪几部分组成？数据从哪来、存在哪、怎么算？数字孪生图、能流图、实景诊断、预测、产品碳足迹、AI 助手分别是怎么实现的？

---

## 1. 一句话概括

这是一个“**数据库 + 计算引擎 + AI 助手 + 可视化网站**”四件套的园区能碳平台：

1. 企业的月度能耗、产值等数据通过**标准 Excel 模板**导入 **PostgreSQL 数据库**；
2. 数据库里的**计算引擎**自动把能耗折成标准煤、按国家核算方法算出碳排放、再算出绿色园区评价指标；
3. **Python 模型**做能碳预测（Chronos-2）和产品碳足迹（Brightway + 天工数据）；
4. **Next.js 网站**把结果画成地图、图表、孪生图；**AI 总管**（DeepSeek）和**小云语音**（千问）用自然语言回答问题。

## 2. 全景图：从数据到页面

```
┌───────────────────────── 应用层（浏览器看到的） ─────────────────────────┐
│ 总览大屏 · 能源管理 · 碳排管理 · 实景诊断 · 企业名录 · 后台（导入/治理）     │
│ 小云语音助手（千问实时语音）     小云总管文字对话（DeepSeek）               │
└──────────────▲─────────────────────────────▲─────────────────────────────┘
               │ 页面数据（服务端渲染）         │ 自然语言提问
┌──────────────┴──────────────┐  ┌───────────┴──────────────────────────────┐
│ 网站服务 apps/web（Next.js） │  │ AI 层 packages/db-agent：总管 Agent + 13 个只读工具│
│ 读数据只调用 db-agent 的函数  │  │ 语音后台 xiaoyun（Node）→ ask_platform_manager │
└──────────────▲──────────────┘  └───────────▲──────────────────────────────┘
               │ 只读 SQL（SET ROLE 最小权限）  │
┌──────────────┴─────────────────────────────┴──────────────────────────────┐
│ 数据层 PostgreSQL（greensystem）+ TimescaleDB，经 SSH 隧道访问             │
│ raw 原始批次 → core 主数据/因子/指标 → fact 事实数据 → mart 展示视图          │
│ engine 计算函数（折标、碳核算、指标、预警）  semantic 语义目录  lab 试验表     │
└──────────────▲──────────────────────────────▲─────────────────────────────┘
               │ 导入通道                       │ 离线模型写回结果
   Excel 模板 / 网站上传 / npm run ingest   packages/forecast（Chronos-2 预测）
   天气同步（高德、NASA POWER）             packages/lca（Brightway + 天工 LCI）
```

**核心原则**：网页和 AI 都**只读**数据库；所有“算”的事情在数据库计算引擎或离线 Python 模型里完成，结果写回数据库，网页只展示结果。这样数字只有一个来源，网页、AI、语音说的数永远一致。

## 4. 数据是怎么流动的

### 4.1 导入：先存原件，再拆成标准数据

1. 企业按模板填 Excel（月度能耗、年度经济、产品产量、资源环境四类模板）。
2. 在网站“后台 → 数据管理”上传，或在命令行运行 `npm run ingest`。
3. 系统先**校验不入库**（dry run），通过后正式导入：
   - 原始文件和每一行原始记录存入 `raw` 层，生成一个**导入批次**号；
   - 引擎函数 `engine.load_batch` 把每行拆成标准事实数据存入 `fact` 层；
   - 旧数据**不删除**，只标记 `is_current = false`，新数据作为当前版本，可追溯。
4. 导入后自动触发**语义治理**：登记新表新字段、AI 起草字段说明、跑数据检测规则（详见 01 号文档）。

### 4.2 计算：数据库里的“计算器”

运行 `engine.run_all(标准版本, 园区, 年份)` 会依次做：

1. **折标准煤**：电 × 0.1229 kgce/kWh、天然气 × 1.3284 kgce/m³……全部来自已审核的因子表 `core.factor`。
2. **碳核算**：按国家发展改革委《关于印发〈工业园区碳排放核算方法〉等的通知》（发改环资〔2025〕910号）附件4：
   - 燃料燃烧（范围一）= 活动量 × 低位热值 × 碳含量 × 氧化率 × 44/12；
   - 外购电、热（范围二）= 用量 × 电网或热力排放因子（每年因子不同）；
   - 绿电交易、自发光伏按零排放处理。
3. **指标计算**：按《绿色工业园区评价要求》2026 版 19 项指标的公式（存在 `core.formula`，需人工批准后才生效）。
4. **预警评估** `engine.evaluate_alerts`：同比偏离超 10%、预算超限、指标未达标、企业强度过高等规则。

> 为什么放在数据库里算？因为数据和公式在同一处，一条 SQL 就能保证全园区口径一致；网页、AI、报表都直接读结果。

## 5. 各个“亮点功能”是怎么实现的

### 5.1 园区总览大屏（卫星地图 + 浮动面板）

- **底图**：高德地图 3D 模式 + 卫星影像图层，镜头倾斜 45°。
- **片区边界**：规划图描出的多边形坐标，先用 **Chaikin 切角算法**平滑 3 次（每次把每个拐角切成两个点，折线就变成圆滑曲线），再画荧光黄实线 + 半透明粗线做外发光。
- **企业标注**：全景时是荧光黄小圆点；点进片区后变成**锥形箭头**（用 Canvas 画一个渐变三角形 + 椭圆顶面，转成图片作为图标）+ **波纹动画**（AntV L7 的 PointLayer 开启 `animate`，在地面画一圈圈扩散的光环）。
- **左右面板**：服务端从数据库取年度能耗、碳排放、达标指标、荣誉、排名，React 组件渲染。

### 5.2 能耗热力孪生（能源页）

“孪生”在这里的意思是：**在真实地理位置上，用模型把企业用能“摊”到空间里，看出园区哪里用能集中**。做法：

1. 在四个规划片区内铺一张**点阵**，间距约 66 米，点必须落在片区多边形内（射线法判断点在多边形内）。
2. 对每个点，计算附近每家企业当月能耗的贡献：贡献 = 企业能耗 × e^(−距离²/2σ²)，σ = 330 米（**高斯核扩散**，离企业越远贡献越小）。
3. 所有贡献相加得到该点的“热度”，再开平方（防止最大的一家把其他都压成蓝色）后映射到 6 段颜色：蓝 → 青 → 绿 → 黄 → 橙 → 红。
4. 用 AntV L7 的 PointLayer 以“叠加发光”模式画出几千个点，叠在高德 3D 暗色底图上。
5. 底部时间轴切换月份时只更新点的数据，不重建图层；年份切换（2021–2025）同理。
6. 月度能耗前三的企业有信息卡 + 锥形箭头 + 波纹。

> 注意：扩散是**可视化模型**，不是厂区内的分项计量。真实计量接入后可换成按厂区、产线的实测值。

### 5.3 能流 / 碳流网络地图

1. 结构：园区 → 两个产业片区 → 每家企业，按能源品种（电网电力、绿电、天然气、热力、油品）分别连线。
2. 每条线是 AntV L7 的**弧线**（arc），线宽按量开方缩放；叠三层：底层半透明弧、上层带**流动光点动画**的弧、再一层**箭头贴图**沿线移动，表示方向。
3. 能流方向是“园区 → 企业”（供能），碳流方向反过来“企业 → 园区”（排放汇聚）。
4. 右上角按钮可以只看某一种能源；默认比例尺固定为“以园区中心为准、约两片区全览的 1.7 倍”，窗口变化时自动重新取景。

### 5.4 实景诊断（诊断页）

思路来自工业监控界面：**位置就是最重要的业务信息**。

1. 底图是卫星实景，选“绿色家居 / 电子信息”片区后镜头按该片区企业分布自动取景、倾斜 55°，能看清厂房屋顶。
2. 每家企业一个锥形箭头：大小表示排放量，颜色表示最严重预警等级，下方波纹，有预警的波纹更大。
3. 园区级预警（如“园区碳排放同比偏离”）会读取预警的**根因记录**（`root_cause.top_contributors`，计算引擎在生成预警时就记录了每家企业贡献多少），把预警落到贡献 ≥10% 的企业位置上。
4. 点击箭头或左侧预警，右侧诊断卡联动：排放、同比、单位产值 CO₂、12 个月排放对比上年、预警证据、匹配的减碳策略。

### 5.5 能碳预测（Chronos-2）

1. **模型**：Chronos-2 是亚马逊开源的时间序列“基础模型”，像大语言模型一样先在海量真实时间序列上预训练，**不需要用本园区数据训练**就能直接预测（零样本）。为什么不用 LSTM？因为每家企业只有约 60 个月数据，从头训练很容易过拟合。
2. **输入**：园区和每家企业的月度综合能耗、碳排放序列（2021 年起）。
3. **输出**：未来 12 个月的 10%、50%、90% 分位数——网页上虚线是中位数，阴影带是 10%–90% 区间。多个对象同时预测，互相借鉴（cross learning）。
4. **回测验证**：用截至前一年的数据预测最近 12 个月，与“去年同月”和“去年同月 × 增速”两种简单方法比较。上次回测园区能耗误差 MAPE 6.8%，明显好于简单方法的 12.9%。
5. **达峰路线图**：2026 年取 Chronos-2 预测，2027–2030 年按两种情景外推——基准情景（增速回落到 4%、电网每年低碳化 1%）和低碳情景（每年多节能 3 个百分点、碳排放/能耗比每年降 6%），得出达峰年份与峰值。
6. 结果写入 `fact.forecast` 表，网页只读。

### 5.6 产品碳足迹与碳轨迹（Brightway + 天工）

1. **背景数据**：天工 LCI 数据库（5,572 个生产过程，每个过程列出投入的原料、能源和排放的温室气体）。
2. **计算引擎 Brightway 2.5**（开源 LCA 工具）：把所有过程组成一个大矩阵 A（谁用了谁多少），排放组成矩阵 B，再乘以 IPCC 100 年全球变暖潜势因子 C。求解 **A·x = f**（要生产 1 单位产品，整个供应链每个过程要运行多少），碳足迹 = C·B·x。这就是“递归”算到整条上游供应链。
3. **园区两条产业链**：
   - 绿色家居：秸秆收集 → 万华禾香无醛秸秆刨花板 → 现代筑美定制衣柜，约 114 kgCO₂e/套；
   - 电子信息：衬底与工艺气体 → 今上半导体 LED 芯片 → 谷麦光电背光模组，约 3.8 kgCO₂e/套。
4. 每个阶段 = 用量 × 因子：原料、运输用天工结果；**园区内生产段**用园区数据库里企业的实际（模拟）排放 ÷ 产量。累计起来就是“碳轨迹”。
5. 结果写入 `lab.product_chain*` 表，网页画瀑布图展示每一步“加了多少碳”。

### 5.7 AI 总管与小云语音

- **AI 总管**（04 号文档详述）：一个 DeepSeek 驱动的 Agent，手里有 13 个只读查询工具。你问“2025 年哪家企业排放最多、比去年降了多少”，它会自己决定调用 `get_carbon_summary` 等工具、拿到数字再回答。**模型从不直接连数据库**，只能通过工具，而工具在只读事务、最小权限角色下运行。
- **小云语音**：浏览器里的小云形象负责录音和播放，后台用千问实时语音模型听懂和说话；遇到园区业务问题，就调用 `ask_platform_manager` 把原话交给同一个 AI 总管——所以文字和语音回答一致。

### 5.8 数据治理与语义目录

- **语义目录**：数据库里每张表、每个字段都有中文说明，AI 写 SQL 前先查目录，知道“哪个字段是什么意思”。
- **自动治理**：导入后、或每小时（Windows 计划任务）检查是否有新表新字段，有的话由 AI 起草说明、跑检测规则（空值、重复、超范围等），发现问题生成工单，管理员在“后台 → 数据治理”审核。
- **兜底**：数据库触发器会记录任何直接用 SQL 写入或改表结构的动作，下一次治理自动跟进。

### 5.9 模拟数据

园区真实数据还没到位，目前多数数据是按规则生成的**模拟数据**（`data/simulated/assumptions-v2.json` 记录全部假设，固定随机种子可复现），走和真实数据完全相同的导入通道，标记为 `estimated`。真实数据导入后会自动替换（旧行标记失效，不删除）。当前情景为“绿色转型”：碳排放 2024 年达峰，2025 年下降约 9%，单位增加值 CO₂ 逐年下降。

## 6. 安全与权限（为什么 AI 不会乱改数据）

| 角色 | 权限 | 谁在用 |
|---|---|---|
| `green_app` | 读写业务数据，不能删表 | 导入、网页读数 |
| `green_agent_ro` | 只读：展示视图、事实表、字典和语义目录，带超时 | AI 自己写的 SQL |
| `green_ddl` | 只能建表、加字段 | 受控的建表工具 |
| `zyz` | 应用登录账号，按需切换到上面的角色 | 网站与 AI 后台 |

- 数据库不对外开放，只能通过 **SSH 隧道**（本机 15432 端口转发到服务器）访问；
- 删除操作在数据库层被禁止（`green_block_drop` 事件触发器）；
- 密钥只放在被 Git 忽略的本机环境文件，不进仓库；
- 网站登录用签名 Cookie，`proxy.ts` 拦截未登录访问。
